Physical BGA ball identities

Implemented core contract
Object pinLabels can use uppercase physical ball names (A1, A2, B1, AA1), as
well as existing numeric / pin<number> keys. The explicit map defines the
package pins. Physical rows sort by length and ASCII, columns numerically;
numeric keys reserve their existing ordinals. Schematic ordinals therefore do
not depend on map insertion order or footprint child order. Changing the set
of package pins can change layout ordinals; physical names remain identity.

Physical names are retained as source_port.name and port_hints. Physical source
ports omit pin_number: their package pin identifier is a string, not a number.
The numeric layout ordinal remains on schematic_port.pin_number, linked by
source_port_id. Footprint pads retain their physical hints and bind to the
corresponding source port. This serializes the mapping without a new JSON field.
Numeric-key pins retain source_port.pin_number; a signal label such as IN4
therefore cannot accidentally replace their numeric package pin identity.

Physical aliases resolve in connections, schematic arrangements and pin styles.
A repeated label such as GND does not imply an internal connection between
physical balls; connect each named ball explicitly to net.GND when appropriate.
A singular selector using an ambiguous alias errors with the physical ball names.
Explicit physical hints take priority over shared signal labels in pad matching.
Existing numeric pins and numeric-key ball aliases retain their behavior.

Validation
Fresh three-ball circuit tests check source/schematic/PCB links and geometry,
reordered maps and footprints, explicit shared nets, ambiguous aliases, unknown
balls, numeric compatibility and multi-letter rows. PCB and schematic snapshots
are included. Existing numeric-pin and internally-connected-pin tests pass.
The previous invalid-key regression now uses INVALID_PIN; A1 is valid.

Export boundary
KiCad requires physical strings for pad numbers, library symbol pin numbers and
symbol-instance pin numbers. The companion https://github.com/tscircuit/circuit-json-to-kicad/pull/634 uses the
physical source-port name at all three boundaries. Older exporter versions use
numeric layout ordinals and need that companion change before BGA export.
